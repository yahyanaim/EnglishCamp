# إعداد النطق الطبيعي من Microsoft Azure

اختير الربط المباشر بـ **Microsoft Azure Speech** بدل توليد بقية ملفات الكلمات مسبقًا. الواجهة والمحتوى لم يتغيرا. يستخدم الخادم المحلي وCloudflare نفس محوّل REST الرسمي، مع بقاء التسجيلات الموجودة متاحة مباشرة.

## إنشاء الخدمة

1. افتح [بوابة Microsoft Azure](https://portal.azure.com/) وسجّل الدخول بحسابك. قد يتطلب إنشاء حساب Azure جديد التحقق من الهوية أو وسيلة دفع بحسب بلدك ونوع الاشتراك؛ هذه خطوة تقوم بها بنفسك.
2. ابحث عن **Speech** وأنشئ موردًا لخدمة الكلام. قد تظهر الخدمة باسم **Azure Speech** أو **Speech in Foundry Tools**.
3. اختر مجموعة موارد، واسمًا مثل `englishcamp-speech`، ومنطقة متاحة. اختر تحديدًا فئة السعر **Free F0**. إذا لم تظهر F0، توقّف ولا تختَر فئة مدفوعة تلقائيًا.
4. بعد إنشاء المورد، افتح **Keys and Endpoint**. ستحتاج إلى أحد المفتاحين وقيمة **Location/Region** الخاصة بالمورد، مثل `westeurope`. استخدم رمز المنطقة، وليس عنوان Endpoint كاملًا.

فئة F0 تتيح حاليًا **500,000 حرف شهريًا** للنطق العصبي، مع حد **20 طلبًا في الدقيقة**. احتفظ بالمورد على F0 إذا أردت استخدام هذه الحصة المجانية. [الأسعار الرسمية](https://azure.microsoft.com/en-us/pricing/details/speech/)، [حدود الاستخدام](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/speech-services-quotas-and-limits).

## تشغيل نسخة Cloudflare المحلية على المنفذ 3034

أُنشئ ملف `.dev.vars` محلي فارغ من قالب المشروع. افتحه داخل مجلد EnglishCamp وضع القيم الحقيقية بين علامتي الاقتباس:

```dotenv
AZURE_SPEECH_KEY="ضع المفتاح هنا داخل الملف المحلي فقط"
AZURE_SPEECH_REGION="westeurope"
```

استبدل `westeurope` بمنطقة موردك إذا كانت مختلفة. لا ترسل المفتاح في المحادثة أو الصور، ولا تضفه إلى GitHub أو متغير يبدأ بـ `NEXT_PUBLIC_`. ملف `.dev.vars` مستثنى من Git. لا تستبدل إعدادات أخرى سبق أن أضفتها إلى الملف.

أعد تشغيل `npm run preview:cloudflare` بعد حفظ الملف. جرّب زر نطق كلمة في **Vocabulary → Word library**. التسجيلات الجاهزة لا تستدعي Azure؛ لذلك اختبر كلمة غير موجودة في التسجيلات الحالية، مثل `absorb`.

## الخادم المحلي العادي

ضع نفس المتغيرين في `.env.local` ثم أعد تشغيل خادم Next.js. لا تحتاج خدمة النطق المباشر إلى Python بعد هذا التعديل. أدوات Python القديمة محفوظة لإنتاج تسجيلات ثابتة عند الحاجة، ولا يستدعيها مسار النطق المباشر.

## عند النشر على Cloudflare

من إعدادات Worker افتح **Variables and Secrets** وأضف `AZURE_SPEECH_KEY` و`AZURE_SPEECH_REGION` كإعدادات للخادم؛ احفظ المفتاح كـ **Secret**. لا تضعه ضمن ملفات الموقع أو متغيرات بناء الواجهة. لا يُرفع `.dev.vars` إلى Cloudflare أو GitHub تلقائيًا.

المفاتيح تبقى على الخادم. تُرسل الكلمات المنشورة إلى Microsoft عند طلب النطق، بينما تظل النصوص الشخصية بحاجة إلى موافقة المستخدم الموجودة في التطبيق. لا تُرسل الملاحظات أو تسجيلات الميكروفون ضمن طلبات توليد النطق.

الأصوات هي `en-GB-SoniaNeural` للإنجليزية و`ar-SA-ZariyahNeural` للعربية. لا يوجد انتقال تلقائي إلى صوت المتصفح الآلي أو إلى خطة استضافة مدفوعة عند تعذّر الخدمة.

تم اختبار الربط ببديل محلي يحاكي استجابة Microsoft، بما يشمل حماية المفتاح والموافقة والتحقق من المصدر وحجم الطلب. لن يُعدّ التشغيل الفعلي مكتملًا قبل إضافة مورد Azure صالح وتجربة استجابة صوتية حقيقية.
